# Context-Insight

Session-level observability for LLM coding agents: import agent session logs and analyze tokens, context, subagents, and skill usage turn by turn.

**[中文文档](README-zh.md)**

## Features

Import SQLite (opencode.db) or JSONL (native Claude Code / Codex `rollout-*.jsonl` / DSH `session.v4.jsonl(.zstd)` / cpx proxy captures; plaintext, `.jsonl.7z` and legacy `.jsonl.gz`, `cpx-` prefix handled) and explore them in the run workbench — every session is a solo run, the single detail surface shared with Opsbot workflow runs. A single "JSONL (auto)" entry detects Claude vs Codex vs DSH per file content — no per-framework picker:

- **Tokens & Cost** — 5-item per-turn token breakdown vs the model's context window, plus cost estimation
- **Active / Wall time** — session detail Wall Clock split (active + inactive = wall) and Active / Wall columns on the homepage: event-clustering semantics (gaps >5min count as inactive, in-flight API calls count as active)
- **Context Growth** — Per-agent context growth curves on a fixed, viewport-adaptive full-width plot with Perf-parity time-window zoom (Ctrl/⌘+wheel cursor-anchored zoom and drag pan act on the time axis only — the chart box never stretches; ticks and the y range re-fit the visible window, curves re-sample in place, click-to-focus) with an on-canvas quick filter, pure-legend chips, an always-visible per-agent stats grid with full untruncated names from a single run-actor naming catalog, animated replay and `/compact` markers; large runs (agent count over a threshold) switch to focus mode — curves default to the peak top-K (with a 峰值 Top re-focus quick button and 全部 as the explicit show-all), legend chips collapse to a preview with an expandable scroll zone plus a search box, and the stats grid caps at top rows with a show-all toggle, while small runs and single sessions keep the flat all-visible behavior
- **Context Governance** — Per-turn LLM input composition: visible messages + stable System overhead
- **Subagent Tracking** — Subagent sessions and dispatch→response bridges, inline in the timeline
- **Turn Player** — The run read as one film: a node status timeline on top (status segments across the run, the active node anchored taller with a persistent identity cluster, generation hairlines) above a generation-grouped node list (member sessions lazily loaded, subagent lanes nested), with the selected turn in a transport-bar player (filmstrip + boundary-crossing prev/next walk) and a delta-priority input card
- **Wire Rounds** (proxy captures) — Per-round full wire input/output, cross-checked against the DB reconstruction; shown with `-a`
- **System-line Noise Governance** (proxy captures) — wire system components carry no message id, so every request re-records them: the token-budget countdown (`<total_tokens>N tokens left</total_tokens>`, pure wire bookkeeping) is stripped wherever it appears (a component left empty is skipped), and static injections riding along every request dedup by their stripped text (kept once, at first appearance). Real system events (context warnings, hook injections, CLAUDE.md, date / environment updates) are all preserved; wire fidelity is untouched (wire replay / skills full-set / full context all read the raw capture, never the Turn table); existing sessions heal on re-import (ranked-prefix drift triggers a full replace)
- **Tool-duration Fidelity** (proxy captures) — history replays never overwrite the first tool_result carrier: completedAt anchors to the true completion moment (the first carrier line), so tool durations are no longer inflated to hours by later requests replaying the messages history (real-world case: a 42ms Bash recorded as 50653.9s); replay lines never produce extra turns; existing sessions heal on re-import
- **Per-turn Duration** (Turns left column) — each row now shows the turn's full wall-clock span instead of model latency: for claude-format sessions (all proxy wire captures + claude native) and native codex, tools execute after generation, so per-turn = generation + slowest parallel tool; native opencode message duration already covers part (tool) execution and stays as-is (no double counting); hovering shows the model/tool breakdown when tools contribute
- **Dual Timestamp Models for Tool Windows** (cc-db-turn native exports) — lake-bundle `.native` members derive tool durations under a second wire model: assistant lines are stamped at request send with duration_ms = request→response and tool-result carriers share the same stamp, so windows are judged per window by gap sign (same-stamp windows span [ts + duration_ms, next request line]) — a 137-member bundle with 4168 tool rounds recovered true millisecond-level windows
- **Skill Events / Coverage / Content** — Per-turn skill events (both wire shapes: claude-code's Read-the-SKILL.md protocol and codex's skills_instructions protocol, where the model reads SKILL.md itself via shell read commands on `exec_command` — native rollouts and cpx captures alike; chained commands like `echo …; cat …/SKILL.md` are detected segment by segment), events attached to the real tool call (real timing, no synthetic `skill/<name>` tool rows polluting the tool stats), available-skills vs used comparison, SKILL.md full-text rebuild (Skill-tool injection, read tools, and shell read commands with range-limit awareness)
- **Agent Definition Recovery** — One-click full text of dispatched agents' `.md` definitions: session system-injection first, disk scan fallback
- **Concept Tracing** — Cross-turn keyword search, propagation chains and DAG; filter by source/thinking/tool
- **File Read Analysis / Restore / Gather** — Duplicate-read detection, per-file line-by-line rebuild, whole-directory rebuild as zip
- **Session Compare** — Two sessions side by side (solo runs, picked by taskId): tokens / cost / latency / tools / subagents
- **Trajectory Scoring** — Six-dimension scorecard (completion veto / trust / quality / efficiency / redundancy / autonomy + custom dims), baseline comparison and scoring profiles; evaluation data exports as a versioned JSON (`insight-score-export@1`) — full member scorecards, the dimension-definition snapshot (dimension ↔ item ↔ weights ↔ aggregation — the matching relations, self-describing) and provenance (insight/scorer versions, profile, timestamps) for self-evolution (RSI) pipelines, from the Score tab's export button or the same endpoint programmatically
- **Audit** — Run-level four-domain auditing (left domain navigation + target list, right report pane): Skill and Agent declarations reconciled against every involved member's transcript (agent targets cover every dispatch tool family — claude Task/Agent, opencode task, codex spawn_agent — with event names matching the swimlane labels) (when the source bundle is still on disk, reconciliation goes through sift's native `--run` — member enumeration, target matching and native call provenance are handled by sift, and the report carries matched-session and call counts; otherwise it falls back to a single multi-transcript pass with cross-member aggregation, member-attributed findings either way), per-member Workflow (main-agent orchestration combined declaration) root-segment reconciliation, and Run as the orchestration-regulation declaration × all members' full sessions in loose mode (no call-slice splitting — auditing orchestration discipline across the whole run; named declarations go through sift's native `--run` loose mode) — reports render from sift JSON as verdict tiles, instruction groups and member badges, with a completion-driven progress bar (counts finished batches only, never regresses across member slices), a declaration-coverage overview (the declaration's original text as snapshotted at reconciliation time, painted green / amber / gray per segment — touched / unverified / unmodeled, hover any segment for its instruction digest), and fail-first instruction ordering
- **Key Redaction** (proxy captures) — API keys never touch disk: masked (`abcd…wxyz`) at the single write chokepoint
- **Data-lake Upload** — Sessions and runs upload to the lake from the unified workbench (row menu / page header): secrets scrubbed, archived under paradigm directories, with baseline slots and task-outcome annotation. Proxy-capture rows offer "also upload the native session" — the native record of the same conversation is located automatically (already-imported rows are taken directly; otherwise the local disk is scanned per framework: Claude / opencode / DSH by session id, Codex by capture time window + first-query anchor), imported first if needed, and lands alongside the capture as a `<sid>.native/` dual record (Codex native ids differ and land under their own id); the CLI gets the same `--with-native`. A missing git-lfs installs itself — any lake action prewarms the bootstrap in the background (public-mirror fallback when GitHub is slow, sha256 pinned), so LFS-mode upload/import needs zero manual setup. Upload completion gets an immediate top-of-screen result HUD (frosted card): success (green check) dismisses itself and closes the dialog with the native-sync outcome as its subtext, failure (red cross) keeps the full error in the dialog for reading and copying, and run uploads with missing-text warnings alert in amber while the full list stays in the dialog — consistent across every upload surface (workbench home, run page)

## Install & Usage

### Option 0: npm install (Recommended)

```bash
npm install -g context-insight
context-insight            # first run: auto-build + migrate (~30s-2min), then start + open browser
```

- Requires Node.js >= 22.14; mainland-China networks can add `--registry=https://registry.npmmirror.com`
- Offline fallback: `npm install -g ./context-insight-<version>.tgz`
- Writable state lives in `~/.context-insight/`; default port 21025 (auto-increments if occupied)
- CLI subcommands pass through: `context-insight upload --file … --list` / `sessions`; short alias `ctxi`
- Python 3 optional (starts the smart-agent analysis backend when present)
- Alternate brand: `npm install -g cannbot-insight` — the same tool published under the CANNBot-Insight name (commands `cannbot-insight` / `cbi`, data dir `~/.cannbot-insight/`); session data is fully interchangeable with context-insight (shared format identity)

| Flag | Effect |
|------|--------|
| `-a`, `--advanced` | Show advanced tabs (wireRounds/replay) |
| `-k`, `--kill` | Stop all insight/smart-agent instances of this repo, then start on 21025 (falls back to the next free port if occupied by others) |
| `-f`, `--fresh` | Clear the build cache and rebuild |
| `-h`, `--help` | Print the full CLI reference — all subcommands and flags (incl. `-v, --version`) |

### Option 1: Web UI from source

```bash
./start.sh              # production mode (default): cached build + zero per-request compile
./start.sh -u           # update deps, then start
./start.sh -f           # force a fresh build
./start.sh -d           # dev mode (hot reload while editing source)
```

- Requires Node.js >= 22.14; `./start.sh` also installs the `cpx` capture command (see `../cpx/README.md`)
- Open `http://localhost:21025`

Log file locations:
- opencode: `~/.local/share/opencode/opencode.db`
- Claude Code: `~/.claude/projects/` (directory auto-scan)
- Codex: `~/.codex/sessions/` (rollout files; subagent sessions merge into their parent)
- DSH: `~/.dsh/sessions/` (`session.v4.jsonl` / `.jsonl.zstd`; subagent sessions merge into their parent)

The Web UI also supports exporting sessions to standalone SQLite or Markdown, plus a fully offline interactive HTML bundle (the real run workbench embedded — every run, solo or multi-member, exports it from the run page header; the offline view mirrors the live default tab surface). The LLM provider panel embeds a known-provider Base URL quick reference.

| Option | Description |
|--------|-------------|
| `--file <path>` | Source path (.db / .jsonl / directory; type auto-detected) |
| `--session-id <id>` | Pick a specific session (skip the interactive picker) |
| `--description <text>` | Upload description |
| `--with-native` | Also upload the native session found on this machine alongside the capture (`<sid>.native/` dual record) |
| `--yes` / `--json` | Skip confirmation / JSON output (script-friendly) |
| `--list` | List available sessions only |
